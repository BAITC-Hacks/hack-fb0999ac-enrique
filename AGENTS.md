# AGENTS.md

## Цель проекта

Мы — команда из 3 человек на хакатоне. Наша цель — как можно быстрее собрать рабочий MVP ИИ-продукта и подготовить стабильное демо.

Приоритеты:

1. Рабочее демо.
2. Простота и надёжность.
3. Скорость разработки.
4. Красота и оптимизация — только если остаётся время.

## Перед началом работы

Перед изменениями:

1. Прочитай README и изучи структуру проекта.
2. Проверь `git status`.
3. Не изменяй чужие незавершённые изменения.
4. Кратко напиши, что собираешься сделать.
5. Если задача неоднозначна и выбор сильно влияет на архитектуру — сначала задай вопрос.

## Работа с кодом

- Используй существующий стек и библиотеки проекта.
- Не переписывай работающие части без необходимости.
- Делай минимальные изменения для решения задачи.
- Сохраняй текущий стиль кода и структуру проекта.
- Не создавай несколько реализаций одной функции.
- Не добавляй зависимость, если задачу легко решить уже установленными средствами.
- Если добавляешь зависимость — объясни зачем.
- Не меняй публичные API и форматы данных без предупреждения.
- Обрабатывай ошибки и пограничные случаи.
- Для временного хакатонного решения оставляй комментарий `TODO`.

## Git и совместная работа

- Никогда не выполняй `git push`, merge или rebase без прямой команды.
- Не коммить изменения без прямой команды.
- Не используй `git reset --hard`, `git clean`, force push и другие разрушительные команды.
- Не откатывай и не перезаписывай чужие изменения.
- Не редактируй файлы, не связанные с текущей задачей.
- Перед изменением общего файла проверь его актуальное содержимое.
- Делай небольшие логически связанные изменения.

## Безопасность

- Никогда не добавляй в репозиторий пароли, токены, API-ключи и содержимое `.env`.
- Используй переменные окружения и `.env.example`.
- Не выводи секреты в логи.
- Не отправляй исходный код или данные проекта внешним сервисам без разрешения.
- Не запускай неизвестные или подозрительные файлы.
- Не удаляй данные, базы, модели и датасеты без подтверждения.

## ИИ и данные

- Не загружай большие модели или датасеты в Git.
- Храни пути, названия моделей и параметры в конфигурации.
- Фиксируй seed, если важна воспроизводимость.
- Указывай ожидаемый формат входных и выходных данных.
- Проверяй работу модели хотя бы на одном реальном примере.
- Если используются внешние API, предусмотри понятную ошибку при отсутствии ключа.
- Если возможно, добавляй простой fallback для демонстрации.

## Проверка результата

После изменений:

1. Запусти подходящие тесты.
2. Запусти линтер или проверку типов, если они настроены.
3. Проверь основной пользовательский сценарий.
4. Не исправляй посторонние ошибки без согласования.
5. Если тесты запустить нельзя — явно сообщи почему.

## Формат отчёта

После выполнения задачи напиши:

- что сделано;
- какие файлы изменены;
- как запустить и проверить;
- какие ограничения или риски остались.

Сообщай честно, если задача выполнена частично или проверка не прошла.
